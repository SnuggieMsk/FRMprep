**Q1.** A fitted logistic PD model has log-odds $$\ln\frac{p}{1-p} = -3.0 + 0.5 \times \text{leverage} + 0.02 \times \text{age}.$$ For a borrower with leverage $= 4$ and age $= 50$, the predicted default probability is closest to:

- A. 0.50
- B. 0.55
- C. 0.45
- D. 0.27

**Answer: A**

We compute the linear predictor (log-odds), then apply the sigmoid.

1. Linear predictor: $$z = -3.0 + 0.5(4) + 0.02(50) = -3.0 + 2.0 + 1.0 = 0.0.$$
2. Sigmoid: $$p = \frac{1}{1 + e^{-z}} = \frac{1}{1 + e^{0}} = \frac{1}{1 + 1} = 0.50.$$

A is correct. Distractor D (0.27) results from a sign error in the exponent, e.g., computing $1/(1+e^{1}) = 1/(1+2.718) = 0.269$ — using $e^{+z}$ wrongly with a nonzero $z$, or mishandling the $-z$. Distractor B (0.55) and C (0.45) arise from arithmetic slips in the linear predictor (e.g., $z = +0.2$ or $z = -0.2$ from miscomputing $0.02 \times 50$ as $0.2$ or dropping a term), then applying the sigmoid. Here every term lands exactly so that $z = 0$ and $p = 0.5$.

📌 Exam tip: Logistic regression: build $z$ from the linear predictor, then $p = 1/(1+e^{-z})$. Note $z = 0 \Rightarrow p = 0.5$, $z > 0 \Rightarrow p > 0.5$, $z < 0 \Rightarrow p < 0.5$. The most common error is a sign slip in the exponent — keep the $-z$.

**Q2.** A default-detection model is evaluated on 2,000 loans of which 100 actually defaulted. The confusion matrix shows TP $= 60$, FN $= 40$, FP $= 240$, TN $= 1{,}660$. The model's precision and recall are closest to:

- A. Precision $= 60\%$, Recall $= 20\%$.
- B. Precision $= 20\%$, Recall $= 60\%$.
- C. Precision $= 60\%$, Recall $= 60\%$.
- D. Precision $= 25\%$, Recall $= 40\%$.

**Answer: B**

We apply the precision and recall definitions to the confusion matrix.

1. **Precision** = TP / (TP + FP) — of the loans flagged as defaults, how many truly defaulted: $$\text{Precision} = \frac{60}{60 + 240} = \frac{60}{300} = 0.20 = 20\%.$$
2. **Recall** = TP / (TP + FN) — of the actual defaults, how many were caught: $$\text{Recall} = \frac{60}{60 + 40} = \frac{60}{100} = 0.60 = 60\%.$$

B is correct. Distractor A swaps the two formulas (computes precision as if it were recall and vice versa) — the single most common confusion-matrix mistake. Distractor C uses TP+FN in both denominators (treating precision like recall). Distractor D uses wrong denominators entirely (e.g., dividing by total predicted or total actual incorrectly). Verify the labels: precision's denominator is everything *predicted positive* (TP+FP); recall's denominator is everything *actually positive* (TP+FN).

📌 Exam tip: Precision = TP/(TP+FP) (denominator = predicted positives). Recall = TP/(TP+FN) (denominator = actual positives). Mnemonic: re**C**all uses the **C**olumn of actuals (TP+FN). Swapping the two is the classic trap.

**Q3.** Using the same model from Q2 (TP $= 60$, FN $= 40$, FP $= 240$, TN $= 1{,}660$ on 2,000 loans), an analyst computes accuracy and the $F_1$ score. Which pair is correct, and what is the key lesson?

- A. Accuracy $= 86\%$, $F_1 = 0.30$; high accuracy masks weak default detection because classes are imbalanced.
- B. Accuracy $= 86\%$, $F_1 = 0.60$; the model is excellent on every metric.
- C. Accuracy $= 14\%$, $F_1 = 0.30$; the model is essentially random.
- D. Accuracy $= 95\%$, $F_1 = 0.40$; precision and recall are both high.

**Answer: A**

We compute accuracy and $F_1$, then interpret in light of class imbalance.

1. **Accuracy** = (TP + TN) / total: $$\frac{60 + 1{,}660}{2{,}000} = \frac{1{,}720}{2{,}000} = 0.86 = 86\%.$$
2. From Q2: Precision $= 0.20$, Recall $= 0.60$.
3. **$F_1$** (harmonic mean of precision and recall): $$F_1 = \frac{2 \times \text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}} = \frac{2 \times 0.20 \times 0.60}{0.20 + 0.60} = \frac{0.24}{0.80} = 0.30.$$
4. **Lesson:** only 100 of 2,000 loans default (5%), so accuracy is dominated by the easy non-default majority. The 86% accuracy looks strong, but precision is just 20% and $F_1$ is a weak 0.30 — accuracy is misleading with imbalanced classes.

A is correct. B uses the wrong $F_1$ (0.60 ignores the low precision; $F_1$ is pulled down by the smaller of precision/recall). C miscomputes accuracy (14% would be the error rate's complement mistake / using FP+FN). D inflates both accuracy and the metrics inconsistently. The harmonic mean penalizes the low precision, which is the whole point.

📌 Exam tip: $F_1 = 2PR/(P+R)$ is the *harmonic* mean — it is dragged toward the *smaller* of precision and recall. With rare events, accuracy is nearly useless (predict "never default" scores ~95%+ with zero recall); judge by precision, recall, $F_1$, and AUC.

**Q4.** A risk team compares a single deep decision tree, a random forest, and a gradient-boosting model. Which statement correctly describes how the ensembles differ from the single tree?

- A. Random forests build trees sequentially, each fitted to the previous tree's residuals, reducing bias.
- B. Random forests average many trees grown on bootstrap samples using a random subset of features at each split, decorrelating the trees and reducing variance; boosting instead builds shallow trees sequentially, each fitted to the prior ensemble's errors, reducing bias (and can overfit if run too long).
- C. Boosting averages independent bootstrap trees in parallel, while random forests build trees sequentially.
- D. A single deep tree has lower variance than a random forest, which is why forests need pruning.

**Answer: B**

The question tests the mechanics of bagging/random forests versus boosting.

1. **Random forest** = bagging (bootstrap-sample trees, then average/majority-vote) **plus** a random subset of features considered at each split. The feature randomization *decorrelates* the trees, cutting ensemble **variance** further than plain bagging.
2. **Boosting** (e.g., gradient boosting) builds **shallow trees sequentially**, each fitted to the *previous ensemble's errors/residuals*. It reduces **bias** as well as variance, but **can overfit** if run too long.
3. A single deep tree has *high* variance (it overfits); ensembles exist to fix that.

B is correct. A describes *boosting*, not random forests (sequential, residual-fitting). C swaps the two methods (boosting is sequential, random forests are parallel/bootstrap-averaged). D is backwards: a single deep tree has *high* variance, and it is the deep single tree that needs pruning — the forest reduces variance by averaging.

📌 Exam tip: Bagging/random forest = *parallel*, bootstrap + random features, averages decorrelated trees, cuts *variance*. Boosting = *sequential*, each tree fixes prior errors, cuts *bias* but can overfit. Mixing up "sequential vs. parallel" is the classic trap.

**Q5.** A bank is choosing a classifier threshold for a default model. Currently the threshold is 0.50. Management wants to catch a larger share of true defaults, accepting more false alarms. Lowering the threshold to 0.30 will:

- A. Increase recall and tend to decrease precision.
- B. Increase precision and decrease recall.
- C. Increase both precision and recall equally.
- D. Have no effect on recall because recall depends only on the model, not the threshold.

**Answer: A**

The question tests the precision–recall trade-off as the classification threshold changes.

1. Lowering the threshold (0.50 → 0.30) makes the model label *more* borrowers as "default" (positive).
2. More positives caught means more true positives are flagged ⇒ **recall (TP/(TP+FN)) rises** — fewer defaults are missed.
3. But casting a wider net also catches more non-defaulters wrongly ⇒ more false positives ⇒ **precision (TP/(TP+FP)) tends to fall**.

A is correct. B reverses the trade-off. C is impossible: precision and recall generally move in *opposite* directions as the threshold shifts — that is the entire point of the trade-off. D is false — recall depends directly on the threshold; lowering it increases recall by definition.

📌 Exam tip: Lower threshold → more positives flagged → higher recall, lower precision (and vice versa). This is why the ROC curve sweeps the threshold from 1 to 0. When missing a default is costlier than a false alarm, lower the threshold to boost recall.

**Q6.** A classifier produces continuous scores. Model A has AUC $= 0.50$; Model B has AUC $= 0.85$. Which interpretation is correct?

- A. Model A has 50% accuracy; Model B has 85% accuracy.
- B. Model A ranks a random positive above a random negative no better than chance; Model B does so 85% of the time, indicating good discrimination independent of any single threshold.
- C. AUC measures recall at the 0.5 threshold, so Model B detects 85% of positives.
- D. AUC of 0.50 is the best possible, and 0.85 indicates a poorly calibrated model.

**Answer: B**

The question tests the meaning of AUC (area under the ROC curve).

1. **AUC** = the probability that a randomly chosen *positive* is scored *higher* than a randomly chosen *negative* — a measure of ranking/discrimination across *all* thresholds.
2. **AUC $= 0.50$** = no better than random ranking (coin flip). **AUC $= 1.0$** = perfect.
3. So Model A discriminates at chance level; Model B correctly ranks a random positive above a random negative 85% of the time — good discrimination, and it is *threshold-independent*.

B is correct. A confuses AUC with *accuracy* — they are different metrics; AUC is not an accuracy figure. C confuses AUC with *recall at a specific threshold* — AUC integrates over all thresholds and is not a single-threshold recall. D is false on both counts: 0.50 is the *worst* (random), not the best, and a high AUC reflects good *discrimination*, not poor calibration (calibration is a separate property from ranking).

📌 Exam tip: AUC = P(random positive scored above random negative); 0.5 = random, 1.0 = perfect, threshold-independent. It is *not* accuracy and *not* recall at 0.5. Use AUC (with precision/recall/F1) for imbalanced-class risk models where raw accuracy misleads.

**Q7.** A quant proposes using plain linear regression (OLS) on a 0/1 default indicator to estimate default probabilities, instead of logistic regression. Which statement best explains why logistic regression is preferred?

- A. OLS on a 0/1 outcome guarantees probabilities between 0 and 1, but logistic regression is faster to estimate.
- B. Linear regression on a 0/1 outcome can predict probabilities below 0 or above 1 and forces constant marginal effects; logistic regression maps the linear predictor through the sigmoid to keep $\hat p \in (0,1)$.
- C. Logistic regression is estimated by OLS, while linear regression uses maximum likelihood, making logistic more efficient.
- D. Linear regression cannot include more than one predictor, whereas logistic regression can.

**Answer: B**

The question tests the linear-vs-logistic contrast for binary outcomes.

1. A plain linear (OLS) model on a 0/1 target produces a fitted value $\hat\beta_0 + \hat\beta_1 X$ that is *unbounded* — it can fall **below 0 or above 1**, which is nonsensical as a probability. It also forces a **constant marginal effect** of each $X$ regardless of the base rate.
2. **Logistic regression** passes the linear predictor through the **sigmoid**, $p = 1/(1+e^{-z})$, which constrains predictions to $(0,1)$ and allows marginal effects to vary with the probability level.
3. This is precisely the problem logistic regression exists to solve.

B is correct. A is backwards: OLS on 0/1 does *not* guarantee $[0,1]$ — that is the core defect; speed is not the issue. C swaps the estimation methods: *logistic* regression uses maximum likelihood, while linear regression uses OLS — the statement reverses them. D is false — linear regression handles many predictors; that is not the distinction.

📌 Exam tip: OLS on a binary outcome (the "linear probability model") can give probabilities outside $[0,1]$ and imposes constant marginal effects — exactly why logistic regression (sigmoid, ML-estimated) exists. GARP tests this contrast directly.
