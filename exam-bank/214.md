**Q1.** A data scientist is building a model to forecast a continuous credit-spread series. She has labeled historical data and wants to (a) tune the regularization parameter $\lambda$ and (b) report an unbiased estimate of real-world performance. She splits the data into training, validation, and test sets. Which workflow is correct?

- A. Fit candidate models on training, choose $\lambda$ using the test set, then report test-set performance.
- B. Fit candidate models on training, choose $\lambda$ using the validation set, then report performance once on the test set.
- C. Fit and tune $\lambda$ on the test set, then report training-set performance.
- D. Combine all three sets, fit and tune simultaneously, and report in-sample performance.

**Answer: B**

The question tests the train/validation/test discipline.

1. **Training set** — used to fit model parameters for each candidate.
2. **Validation set** — used to *compare candidates and tune hyperparameters* such as $\lambda$. This keeps tuning decisions separate from the final performance estimate.
3. **Test set** — used **exactly once, at the end**, to give an *unbiased* estimate of out-of-sample performance.

B is correct. A commits the headline trap: tuning $\lambda$ on the test set *contaminates* it, so the reported performance is optimistically biased — selecting on the test set turns it into a second validation set. C reports training-set performance (always optimistic, reflects fit not generalization) and also tunes on test data. D reports in-sample performance after pooling everything, which gives no genuine out-of-sample read at all.

📌 Exam tip: Hyperparameters ($\lambda$, $K$, tree depth) are tuned on *validation* data; the *test* set is touched only once for the final unbiased estimate. Any tuning or model selection that "peeks" at the test set inflates reported performance.

**Q2.** A standardized feature matrix is fed to both ridge and LASSO regressions on a dataset with several highly collinear predictors. Which statement correctly contrasts the two methods?

- A. Ridge can drive some coefficients exactly to zero, performing feature selection; LASSO only shrinks.
- B. LASSO can drive some coefficients exactly to zero (sparse model / feature selection); ridge shrinks all coefficients toward zero but rarely to exactly zero.
- C. Both ridge and LASSO leave coefficients unbiased relative to OLS.
- D. As $\lambda \to \infty$, ridge converges to ordinary least squares while LASSO converges to zero coefficients.

**Answer: B**

The question contrasts the L2 (ridge) and L1 (LASSO) penalties.

1. **Ridge (L2)** penalizes $\sum_j \beta_j^2$: it shrinks all coefficients toward zero (sharing weight among collinear features) but **does not set them exactly to zero**.
2. **LASSO (L1)** penalizes $\sum_j |\beta_j|$: its corner geometry drives some coefficients **exactly to zero**, producing a *sparse* model and performing **feature selection**.
3. With collinearity, ridge spreads weight across the correlated group, while LASSO tends to pick one and zero the others.

B is correct. A reverses the two methods (it is LASSO, not ridge, that zeroes coefficients). C is false: regularization *deliberately introduces bias* (accepting bias to cut variance) — that is the whole point of the bias–variance trade-off. D reverses the limiting behavior: as $\lambda \to \infty$ *both* shrink coefficients *toward zero*; it is $\lambda = 0$ that recovers OLS, not $\lambda \to \infty$.

📌 Exam tip: LASSO (L1) = sparse, does feature selection (exact zeros); ridge (L2) = shrinks all, handles collinearity by sharing weight. $\lambda = 0$ → OLS; $\lambda \to \infty$ → everything shrinks to zero. Regularization trades bias for lower variance.

**Q3.** In K-means clustering with standardized features, two current centroids are $c_1 = (1, 1)$ and $c_2 = (5, 4)$. A point $x = (3, 4)$ must be assigned. Using Euclidean distance, the assignment and reason are:

- A. Cluster 1, because $d_1 = 2.83 < d_2 = 3.61$.
- B. Cluster 2, because $d_2 = 2.00 < d_1 = 3.61$.
- C. Cluster 1, because $d_1 = 3.61 < d_2 = 2.00$.
- D. Cluster 2, because $d_2 = 2.83 < d_1 = 2.00$.

**Answer: B**

We compute the Euclidean distance from $x$ to each centroid and assign to the nearer.

1. Distance to $c_1 = (1,1)$: $$d_1 = \sqrt{(3-1)^2 + (4-1)^2} = \sqrt{4 + 9} = \sqrt{13} = 3.606.$$
2. Distance to $c_2 = (5,4)$: $$d_2 = \sqrt{(3-5)^2 + (4-4)^2} = \sqrt{4 + 0} = \sqrt{4} = 2.000.$$
3. Compare: $d_2 = 2.00 < d_1 = 3.61$, so assign $x$ to **cluster 2**. Centroid 2 then moves toward $x$ at the update step.

B is correct. A computes a wrong $d_1$ (2.83 would be $\sqrt{8}$, mis-subtracting coordinates) and reaches the wrong cluster. C has the right distances but reads the inequality backwards (assigns to the *farther* centroid). D scrambles both distances. The key steps are squaring coordinate differences correctly and assigning to the *smallest* distance.

📌 Exam tip: K-means assigns each point to the *nearest* centroid by (squared) Euclidean distance, then recomputes centroids as cluster means. Standardize features first so no single large-scale feature dominates the distance. Watch the inequality direction — nearest wins.

**Q4.** A PCA is run on daily changes of a set of 10 government-bond yields across maturities. The analyst reports the first three principal components explain 96% of total variance. Which interpretation is most consistent with the standard finance result?

- A. The three PCs are economically interpretable as level, slope, and curvature, with the first PC (level) explaining the bulk of variance.
- B. Each of the three PCs is correlated with the others, which is why they jointly explain so much.
- C. PCA should be run on the raw (unstandardized) yields, and the components have direct economic meaning by construction.
- D. The first PC captures idiosyncratic noise; the last PC captures the parallel shift.

**Answer: A**

The question tests the canonical yield-curve PCA result.

1. PCA produces **orthogonal (uncorrelated)** linear combinations ordered by variance explained. The **first PC** is the direction of maximum variance.
2. For yield-curve changes, the first three PCs are conventionally interpreted as **level, slope, and curvature**, together explaining 95%+ of variance — with the **level** (roughly parallel shift) PC explaining the largest share.
3. This dimensionality reduction (10 yields → 3 factors) is a finance staple.

A is correct. B is false: principal components are *uncorrelated by construction* (orthogonal) — they are not correlated with each other. C is wrong on two points: features should be **standardized** before PCA, and PCs generally **lack direct economic interpretation** (the level/slope/curvature labels are an interpretive overlay, a known cost of dimension reduction, not a built-in property). D reverses the ordering: the *first* PC (largest variance) is the level/parallel shift, not noise; idiosyncratic noise lands in the *last*, low-variance PCs.

📌 Exam tip: Yield-curve PCA → ~3 PCs (level, slope, curvature) explaining 95%+ of variance, with *level* dominant and first. PCs are orthogonal/uncorrelated and ordered by variance; standardize first, and remember PCs are not inherently economically interpretable.

**Q5.** A flexible neural network achieves near-zero error on the training set, but its error on the validation set is large and *rises* as model complexity increases further. Using the bias–variance decomposition, the diagnosis and remedy are:

- A. Underfitting (high bias); increase model complexity.
- B. Overfitting (high variance); reduce complexity or apply regularization / early stopping.
- C. Irreducible noise dominates; nothing can be done.
- D. The model is well-tuned at the current complexity; deploy it.

**Answer: B**

The question tests recognition of overfitting via the bias–variance trade-off.

1. Expected prediction error decomposes as $$E[(y-\hat f)^2] = \text{Bias}^2 + \text{Variance} + \sigma^2_{\text{noise}}.$$
2. **Overfitting (high variance)** signature: training error very low (the model memorizes training noise) while **validation error is large and turns upward** as complexity grows. That is exactly what is described.
3. Remedies: reduce complexity, regularize (ridge/LASSO/dropout), or use early stopping; choose complexity where *validation* error is minimized.

B is correct. A describes the opposite problem — underfitting (high bias) shows poor performance *both* in-sample and out-of-sample, not near-zero training error; increasing complexity would make overfitting worse. C wrongly attributes the rising validation error to irreducible noise — irreducible noise is a constant floor and does not *rise* with complexity. D is contradicted by the rising validation error; the model is past its optimal complexity.

📌 Exam tip: Low training error + high (and rising) validation error = overfitting / high variance. Underfitting = high error everywhere. Pick complexity at the validation-error minimum, and use regularization or early stopping to control variance.

**Q6.** Which statement best captures a core *philosophical* difference between machine-learning methods and classical econometrics?

- A. Econometrics prioritizes out-of-sample predictive accuracy and tolerates opaque models, while ML insists on unbiased, interpretable parameters.
- B. ML prioritizes out-of-sample predictive accuracy and validates empirically on held-out data, tolerating biased or opaque models, while classical econometrics emphasizes unbiased, interpretable parameters and hypothesis tests grounded in distributional theory.
- C. Both ML and econometrics rely primarily on hypothesis tests derived from distributional assumptions and avoid held-out validation.
- D. ML cannot handle nonlinearities or large feature sets, which is why econometrics is preferred for big data.

**Answer: B**

The question tests the ML-vs-econometrics contrast.

1. **Classical econometrics**: theory-driven, small interpretable models; focus on *unbiased parameter estimates* and *hypothesis testing* grounded in distributional theory.
2. **Machine learning**: prioritizes *out-of-sample predictive accuracy*; tolerates biased or opaque ("black-box") models; handles large feature sets and nonlinearities automatically; validates *empirically* on held-out data rather than via distributional theory.

B is correct. A swaps the two paradigms' priorities entirely. C is false — ML specifically relies on *held-out (empirical) validation* rather than distribution-based hypothesis tests, and econometrics is the one leaning on distributional theory. D is backwards: ML *excels* at nonlinearities and large feature sets; that is one of its main advantages over classical econometrics.

📌 Exam tip: ML = predictive accuracy, empirical (held-out) validation, tolerates bias/opacity, scales to many features and nonlinearities. Econometrics = interpretable parameters, unbiasedness, hypothesis tests from distributional theory. Do not let answer choices swap these.

**Q7.** A modeler must encode a categorical feature "credit rating bucket" with values {AAA, AA, A, BBB} and a separate nominal feature "industry sector" with 11 unordered categories, before feeding a K-means model. Which preparation is most appropriate?

- A. Use ordinal encoding for both features, since all categories can be numbered.
- B. Use ordinal encoding for the rating bucket (genuinely ordered) and one-hot/dummy encoding for the unordered industry sector; standardize before clustering.
- C. Use one-hot encoding for the rating bucket and ordinal encoding for industry sector.
- D. Leave both as text labels; K-means handles strings directly.

**Answer: B**

The question tests categorical-variable handling and the need to standardize before distance-based clustering.

1. **Ordinal encoding** is appropriate only when categories are *genuinely ordered*. Credit ratings (AAA > AA > A > BBB) have a natural order, so ordinal encoding preserves meaningful information.
2. **Industry sector** is *nominal* (unordered) — assigning it numbers 1–11 would impose a false ordering and distort Euclidean distances. Use **one-hot/dummy encoding** (one column per category).
3. K-means is distance-based, so features must be **standardized** first to prevent large-scale features from dominating.

B is correct. A wrongly imposes order on the unordered sector variable (false ordinality distorts distances). C reverses the two: it ordinal-encodes the unordered sector and one-hot-encodes the naturally ordered rating, discarding the rating's order information and mis-ordering sectors. D is false — K-means requires numeric feature vectors; it cannot operate on raw text labels.

📌 Exam tip: Ordinal encoding only for *genuinely ordered* categories; one-hot/dummy encoding for *nominal* (unordered) ones. Always standardize features before distance- or penalty-based methods (K-means, KNN, ridge/LASSO, SVM) so units don't dominate.
