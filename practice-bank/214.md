**Q1.** Building a model to predict whether a loan will default (yes/no) using historical data that is already labeled as "defaulted" or "not defaulted" is an example of:
- A. Unsupervised learning.
- B. Supervised classification.
- C. Reinforcement learning.
- D. Supervised regression.

**Answer: B**

The question asks which type of machine learning matches this task.

Two clues decide it. First, the data are labeled — each past loan already has a known outcome (defaulted or not). Labeled data with a target to predict means supervised learning. Second, the target is a category (default / no default), not a continuous number, which makes it classification rather than regression. So the answer is B.

Why the others are wrong:
- A. Unsupervised learning uses unlabeled data to find structure (like clustering). Here the data ARE labeled, so it is not unsupervised.
- C. Reinforcement learning learns a sequence of actions from reward signals by trial and error. There is no sequential agent or reward here.
- D. Supervised regression predicts a continuous number (like a dollar amount). Default/no-default is a category, so it is classification, not regression.

Think of supervised learning like studying with an answer key: every example comes with its correct answer, and you learn to predict the answer for new cases. A yes/no answer makes it classification.

📌 Exam tip: Labeled data → supervised. Categorical target → classification; continuous target → regression. No labels → unsupervised.

**Q2.** Which regularization penalty can shrink some coefficients exactly to zero, effectively performing variable selection?
- A. Ridge (L2 penalty).
- B. LASSO (L1 penalty).
- C. Both perform variable selection equally.
- D. Neither can set coefficients to zero.

**Answer: B**

The question asks which penalty produces sparse models with some coefficients set to exactly zero.

LASSO uses an L1 penalty (sum of absolute values of coefficients, $$\lambda\sum_j|\beta_j|$$). The geometry of this penalty has "corners" that push some coefficients all the way to exactly zero, dropping those features entirely — that is automatic variable selection. Ridge uses an L2 penalty (sum of squared coefficients) which only shrinks coefficients toward zero but never exactly to zero. The answer is B.

Why the others are wrong:
- A. Ridge shrinks coefficients smoothly toward zero but keeps all of them nonzero, so it does not perform variable selection.
- C. They are NOT equal: only LASSO produces exact zeros.
- D. LASSO clearly can set coefficients to zero, so "neither" is wrong.

Think of LASSO as a budget so tight it forces you to drop some items entirely, while ridge just makes you buy smaller amounts of everything.

📌 Exam tip: LASSO (L1) → sparse models, exact zeros, feature selection. Ridge (L2) → shrinks all coefficients but keeps them. Elastic net mixes both.

**Q3.** A model's training error is very low, but its validation error is large and grows as the model becomes more complex. This pattern indicates:
- A. Underfitting (high bias).
- B. Overfitting (high variance).
- C. A well-tuned model.
- D. Irreducible noise only.

**Answer: B**

The question describes a model that does great on training data but poorly on new (validation) data.

This is the classic signature of overfitting: the model has memorized the noise in the training set, so training error keeps falling, but it fails to generalize, so validation error rises. Overfitting corresponds to high variance — the model is too sensitive to the particular training sample. The answer is B.

Why the others are wrong:
- A. Underfitting (high bias) shows poor performance on BOTH training and validation data because the model is too simple. Here training error is low, so it is not underfitting.
- C. A well-tuned model has low validation error, not large and rising validation error.
- D. Irreducible noise is a fixed floor on error; it cannot explain a widening GAP between training and validation error as complexity grows.

Think of a student who memorizes the exact practice questions (low training error) but bombs the real exam with new questions (high validation error) — they overfit to the practice set.

📌 Exam tip: Low training error + high/rising validation error = overfitting (high variance). Cure with simpler models, regularization, or more data. Choose complexity where VALIDATION error is minimized.

**Q4.** In the bias–variance decomposition of expected prediction error, which component cannot be reduced no matter how good the model is?
- A. Bias squared.
- B. Variance.
- C. The irreducible noise term $$\sigma^2_{\text{noise}}$$.
- D. The validation error.

**Answer: C**

The question asks which part of prediction error is fixed and unavoidable.

The expected prediction error decomposes as:
$$E[(y - \hat f)^2] = \text{Bias}^2 + \text{Variance} + \sigma^2_{\text{noise}}$$

The first two pieces depend on the model: you can lower bias with more flexibility, and lower variance with simpler models or regularization. But the last piece, the irreducible noise $$\sigma^2_{\text{noise}}$$, comes from inherent randomness in the data itself and cannot be removed by any model. The answer is C.

Why the others are wrong:
- A. Bias squared CAN be reduced by making the model more flexible/complex.
- B. Variance CAN be reduced by simplifying the model, regularizing, or adding data.
- D. Validation error is a measured quantity, not a fixed component of the decomposition; it can change as you tune the model.

Think of trying to predict a coin flip with extra information: even a perfect model can't beat the genuine randomness of the coin — that randomness is the irreducible noise.

📌 Exam tip: Error = Bias² + Variance + Irreducible noise. Only the irreducible noise cannot be reduced. The bias–variance trade-off is about balancing the first two.

**Q5.** Why must features often be standardized (e.g., $$z = (x - \mu)/\sigma$$) before applying methods like K-means, KNN, or ridge/LASSO?
- A. To make the target variable normally distributed.
- B. So features measured in large units don't dominate distance or penalty calculations.
- C. To remove all correlation between features.
- D. To convert categorical variables into numbers.

**Answer: B**

The question asks the purpose of standardizing features for distance- and penalty-based methods.

Methods like K-means and KNN use distances, and ridge/LASSO penalize coefficient sizes. If one feature is measured in large units (say, salary in dollars) and another in small units (say, years of experience), the large-unit feature will dominate the distance or penalty just because of its scale, not its importance. Standardizing puts all features on a comparable scale ($$z = (x-\mu)/\sigma$$) so each contributes fairly. The answer is B.

Why the others are wrong:
- A. Standardizing features does not make the target variable normal; it rescales the inputs, and it is about scale, not normality.
- C. Standardization changes scale but does NOT remove correlation between features (that is what PCA does).
- D. Converting categories to numbers is one-hot/ordinal encoding, a separate step from standardization.

Think of comparing people by height in millimeters and weight in tons: without rescaling, the millimeter numbers (huge) would swamp the ton numbers (tiny). Standardizing levels the playing field.

📌 Exam tip: Standardize before distance/penalty-based methods (KNN, K-means, SVM, ridge, LASSO, PCA) so scale differences don't bias the result.

**Q6.** In K-means clustering with centroids $$c_1 = (0, 0)$$ and $$c_2 = (4, 2)$$, to which cluster is the point $$x = (3, 0)$$ assigned (using Euclidean distance)?
- A. Cluster 1, because $$d_1 = 3.00 < d_2 = 2.24$$.
- B. Cluster 2, because $$d_2 = 2.24 < d_1 = 3.00$$.
- C. Cluster 1, because it is closer to the origin.
- D. Neither; the point is equidistant.

**Answer: B**

The question asks you to assign a point to the nearer centroid in K-means.

K-means assigns each point to the centroid with the smallest Euclidean distance. Compute both distances.

Distance to $$c_1 = (0,0)$$:
$$d_1 = \sqrt{(3-0)^2 + (0-0)^2} = \sqrt{9 + 0} = \sqrt{9} = 3.00$$

Distance to $$c_2 = (4,2)$$:
$$d_2 = \sqrt{(3-4)^2 + (0-2)^2} = \sqrt{(-1)^2 + (-2)^2} = \sqrt{1 + 4} = \sqrt{5} = 2.24$$

Compare: $$d_2 = 2.24 < d_1 = 3.00$$, so the point goes to cluster 2. The answer is B.

Why the others are wrong:
- A. It has the inequality backwards: $$2.24$$ is smaller, so the point is closer to cluster 2, not cluster 1.
- C. "Closer to the origin" sounds intuitive but is wrong here — the actual distances show cluster 2 is nearer.
- D. The distances differ ($$3.00$$ vs $$2.24$$), so the point is not equidistant.

Think of two ice-cream trucks: you walk to whichever one is the shorter actual distance away, not the one that just "feels" closer.

📌 Exam tip: K-means assigns each point to the nearest centroid by Euclidean distance $$\sqrt{\sum(x_i - c_i)^2}$$. Compute both, pick the smaller.

**Q7.** In a principal components analysis (PCA) of daily yield-curve changes, the first principal component typically represents:
- A. Curvature (twist) of the curve.
- B. A parallel level shift of the whole curve.
- C. Idiosyncratic measurement noise.
- D. The slope (steepening/flattening).

**Answer: B**

The question asks what the first principal component of yield-curve moves usually captures.

PCA orders components by how much variance they explain. For yield curves, the first PC — the direction of maximum variance — is a level shift: all maturities moving up or down together in roughly parallel fashion. This typically explains the large majority of yield-curve variance. The second PC is slope (steepening/flattening) and the third is curvature. The answer is B.

Why the others are wrong:
- A. Curvature is usually the THIRD principal component, explaining much less variance.
- C. Idiosyncratic noise is captured by the last, lowest-variance components, not the first.
- D. Slope is usually the SECOND principal component, not the first.

Think of the three main ways a curve moves: the biggest, most common move is the whole curve shifting up or down together (level) — that's PC1.

📌 Exam tip: Yield-curve PCA → PC1 = level, PC2 = slope, PC3 = curvature; together they explain 95%+ of variance. PC1 (level) dominates.

**Q8.** What is the correct role of the test data set in machine learning?
- A. To fit (estimate) the model's parameters.
- B. To tune hyperparameters and compare candidate models.
- C. To be used once, at the very end, for an unbiased estimate of real-world performance.
- D. To be reused repeatedly to maximize accuracy.

**Answer: C**

The question asks what the test set is for.

The three data splits have distinct jobs: the training set fits the model's parameters, the validation set tunes hyperparameters and compares models, and the test set is held back and used only once, at the very end, to give an honest, unbiased estimate of how the model will perform in the real world. The answer is C.

Why the others are wrong:
- A. Fitting model parameters is the training set's job, not the test set's.
- B. Tuning hyperparameters and comparing models is the validation set's job. Using the test set for this contaminates it and makes performance look optimistically better than reality.
- D. Reusing the test set repeatedly defeats its purpose — each peek leaks information and biases the final estimate upward. It should be touched only once.

Think of the test set like the final exam: you study with practice material (training/validation), but you only sit the real exam once, and peeking at it beforehand would make your "grade" meaningless.

📌 Exam tip: Train = fit parameters; Validation = tune hyperparameters/compare models; Test = used ONCE for final unbiased performance. Tuning on the test set is a classic trap.

**Q9.** When splitting time-series data into training and test sets, why must you avoid randomly shuffling the observations?
- A. Random shuffling makes the model train faster.
- B. Shuffling lets future information leak into the training set, inflating performance.
- C. Time-series data cannot be standardized.
- D. Shuffling always increases the bias of the model.

**Answer: B**

The question asks why chronological order matters when splitting time-series data.

In a time series, the goal is to predict the future from the past. If you randomly shuffle and then split, some future observations can land in the training set while their past lands in the test set. The model then effectively "sees the future" during training — data leakage — which makes its test performance look far better than it would in real-life forecasting. To prevent this, splits must respect chronology: train on earlier data, test on later data. The answer is B.

Why the others are wrong:
- A. Training speed is unrelated to whether you shuffle; this is not the concern.
- C. Time-series data can be standardized just fine; standardization is unrelated to the shuffling problem.
- D. Shuffling does not "always increase bias"; the specific danger is leakage of future information (optimistic, biased performance estimates), not a general bias increase.

Think of it like studying for an exam using next week's actual answers mixed into your practice set — you'd score great in practice but learn nothing useful for the real, future test.

📌 Exam tip: For time-series data, keep splits chronological (train on past, test on future). Random shuffling causes look-ahead/data leakage.

**Q10.** In K-means clustering, the within-cluster sum of squares (inertia) always decreases as the number of clusters $$K$$ increases. Given this, how is a good value of $$K$$ typically chosen?
- A. Pick the largest possible $$K$$ to minimize inertia.
- B. Pick $$K$$ at the "elbow" of the inertia curve, or maximize the silhouette score.
- C. Pick $$K = 1$$ to keep the model simple.
- D. Pick $$K$$ equal to the number of features.

**Answer: B**

The question asks how to select the number of clusters when inertia keeps falling as $$K$$ grows.

Since inertia (within-cluster sum of squares) always decreases as you add more clusters, you cannot just minimize inertia — that would push you to give every point its own cluster. Instead you look for the "elbow," the point where adding more clusters stops giving a big drop in inertia, or you maximize the silhouette score (which balances how tight clusters are against how separated they are). The answer is B.

Why the others are wrong:
- A. The largest $$K$$ does minimize inertia (each point in its own cluster gives inertia of zero) but is useless — it creates no meaningful grouping. This is exactly the trap.
- C. $$K = 1$$ lumps everything into one cluster, which gives the maximum inertia and finds no structure.
- D. There is no reason for $$K$$ to equal the number of features; clusters and features are unrelated counts.

Think of choosing how many folders to sort photos into: too few and everything is jumbled; one folder per photo is silly; the "elbow" is the sweet spot where extra folders stop meaningfully helping.

📌 Exam tip: Inertia always falls as $$K$$ rises, so use the elbow method or the silhouette score (range $$-1$$ to $$1$$) to pick $$K$$. Also run multiple random starts, since results depend on initialization.
