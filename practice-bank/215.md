**Q1.** A logistic regression model gives a borrower log-odds of $$z = 1.0$$. The predicted probability of default is closest to:
- A. 50.0%
- B. 73.1%
- C. 26.9%
- D. 100%

**Answer: B**

The question asks you to turn a log-odds value into a probability using the logistic (sigmoid) function.

The sigmoid formula converts the linear score $$z$$ into a probability between 0 and 1:
$$p = \frac{1}{1 + e^{-z}}$$

Plug in $$z = 1.0$$:
$$p = \frac{1}{1 + e^{-1}} = \frac{1}{1 + 0.3679} = \frac{1}{1.3679} = 0.731$$

So the probability is about 73.1%, and the answer is B.

Why the others are wrong:
- A. 50.0% corresponds to $$z = 0$$ (when $$e^0 = 1$$, $$p = 1/2$$). Here $$z = 1.0$$, which is above zero, so $$p$$ must be above 50%.
- C. 26.9% is $$1 - 0.731$$, i.e., the probability of NOT defaulting (or using $$e^{+1}$$ instead of $$e^{-1}$$ in the denominator). It is the complement, not the answer asked for.
- D. 100% would require $$z \to +\infty$$. A finite $$z = 1$$ can never reach 1.

Think of the sigmoid as an S-shaped squashing function: it takes any score and gently squeezes it into a probability between 0 and 1, with $$z = 0$$ mapping to the middle (50%).

📌 Exam tip: $$p = 1/(1+e^{-z})$$. Memorize landmarks: $$z=0 \Rightarrow 50\%$$, positive $$z \Rightarrow$$ above 50%, negative $$z \Rightarrow$$ below 50%.

**Q2.** A fitted logistic model is $$\ln\frac{p}{1-p} = -4 + 0.8 \times \text{leverage}$$. For a borrower with leverage = 5, the predicted default probability is:
- A. 0.50
- B. 0.27
- C. 0.73
- D. 0.12

**Answer: A**

The question asks for the default probability from a logistic model at a given leverage.

Step 1 — compute the log-odds score $$z$$:
$$z = -4 + 0.8 \times 5 = -4 + 4 = 0$$

Step 2 — convert to a probability with the sigmoid:
$$p = \frac{1}{1 + e^{-z}} = \frac{1}{1 + e^{0}} = \frac{1}{1 + 1} = \frac{1}{2} = 0.50$$

So the answer is A.

Why the others are wrong:
- B and C. 0.27 and 0.73 correspond to $$z = -1$$ and $$z = +1$$ respectively — they'd come from arithmetic slips in computing $$z$$ (for example using leverage 3.75 or 6.25).
- D. 0.12 corresponds to a clearly negative $$z$$ (around $$-2$$), which would result from a larger intercept or smaller leverage.

The key insight: when $$z$$ works out to exactly 0, the probability is exactly one-half, regardless of the model's coefficients.

📌 Exam tip: Two steps every time — (1) compute $$z = \beta_0 + \beta_1 X$$, (2) apply $$p = 1/(1+e^{-z})$$. A score of $$z=0$$ always gives $$p = 0.50$$.

**Q3.** Why is plain linear regression generally inappropriate for modeling a binary (0/1) outcome, which is why logistic regression is preferred?
- A. Linear regression cannot include more than one predictor.
- B. Linear regression can predict probabilities below 0 or above 1 and forces constant marginal effects.
- C. Linear regression requires the outcome to be normally distributed.
- D. Logistic regression is estimated by OLS, which is more accurate.

**Answer: B**

The question asks for the core reason logistic regression exists for binary outcomes.

A probability must lie between 0 and 1. Plain linear regression fits a straight line that can keep rising or falling without limit, so it can produce predicted "probabilities" below 0 or above 1 — which are meaningless. It also forces a constant marginal effect (the same change in probability per unit of $$X$$ everywhere), which is unrealistic near 0 and 1. Logistic regression's S-shaped sigmoid keeps predictions inside (0,1) and lets the marginal effect taper off at the extremes. The answer is B.

Why the others are wrong:
- A. Linear regression can absolutely include many predictors; that is not the issue.
- C. Linear regression does not require the OUTCOME to be normal (it is about the errors), and that is not the reason logistic models are used for 0/1 outcomes.
- D. Logistic regression is estimated by maximum likelihood, NOT OLS — so this statement is factually wrong.

Think of trying to fit a straight ramp to something that must stay between the floor and the ceiling: the ramp eventually shoots through both. The S-curve bends to stay inside.

📌 Exam tip: Use logistic (not linear) regression for binary outcomes — it keeps $$\hat p \in (0,1)$$ and is fit by maximum likelihood, not OLS.

**Q4.** A default model evaluated on 1,000 loans produces TP = 30, FN = 20, FP = 70, TN = 880. Its recall (sensitivity) is:
- A. 30%
- B. 60%
- C. 91%
- D. 43%

**Answer: B**

The question asks for recall from a confusion matrix.

Recall (also called sensitivity or the true-positive rate) measures the fraction of actual positives that the model correctly caught:
$$\text{Recall} = \frac{TP}{TP + FN}$$

Here the actual positives (true defaults) are $$TP + FN = 30 + 20 = 50$$. Of these, 30 were correctly flagged:
$$\text{Recall} = \frac{30}{30 + 20} = \frac{30}{50} = 0.60 = 60\%$$

So the answer is B.

Why the others are wrong:
- A. 30% is the precision: $$TP/(TP+FP) = 30/(30+70) = 30/100$$. Precision answers a different question (of the alarms raised, how many were real).
- C. 91% is the accuracy: $$(TP+TN)/\text{total} = (30+880)/1000$$. Accuracy mixes in all the correct negatives.
- D. 43% does not match any standard metric here; it is a distractor.

Recall asks: "Of all the loans that truly defaulted, what share did we catch?" Here we caught 30 of the 50, so 60%.

📌 Exam tip: Recall $$= TP/(TP+FN)$$ (caught actual positives). Precision $$= TP/(TP+FP)$$ (correct among flagged). Don't swap their denominators.

**Q5.** Using the same model (TP = 30, FN = 20, FP = 70, TN = 880), what is the precision?
- A. 30%
- B. 60%
- C. 91%
- D. 70%

**Answer: A**

The question asks for precision from the confusion matrix.

Precision measures, among all the cases the model flagged as positive, how many were actually positive:
$$\text{Precision} = \frac{TP}{TP + FP}$$

The model flagged $$TP + FP = 30 + 70 = 100$$ loans as defaults. Of those, 30 were genuine:
$$\text{Precision} = \frac{30}{30 + 70} = \frac{30}{100} = 0.30 = 30\%$$

So the answer is A.

Why the others are wrong:
- B. 60% is the recall ($$TP/(TP+FN) = 30/50$$) — that uses the false NEGATIVES in the denominator, not false positives.
- C. 91% is the accuracy, which mixes in all the true negatives.
- D. 70% is just the false-positive count expressed as a percent of the flagged loans, i.e., $$1 - \text{precision}$$, not precision itself.

Precision asks: "Of all the alarms we rang, how many were real?" We rang 100 alarms and only 30 were genuine defaults, so 30%.

📌 Exam tip: Precision uses FALSE POSITIVES in the denominator ($$TP/(TP+FP)$$); recall uses FALSE NEGATIVES ($$TP/(TP+FN)$$). Keep the two denominators straight.

**Q6.** Why is accuracy a poor metric for evaluating a default model when only 2% of loans default?
- A. Accuracy cannot be computed for imbalanced data.
- B. A model that predicts "no default" for everyone scores 98% accuracy with zero recall.
- C. Accuracy always equals the AUC.
- D. Accuracy overweights the false positives.

**Answer: B**

The question asks why accuracy misleads when one class is rare.

When defaults are rare (2%), a lazy model that simply predicts "no default" for every loan is correct on the 98% that don't default — giving 98% accuracy. Yet it catches zero actual defaults (recall = 0%), so it is useless for the very thing it's meant to detect. High accuracy hides this complete failure. The answer is B.

Why the others are wrong:
- A. Accuracy can still be computed for imbalanced data; the problem is that the number is misleading, not that it's undefined.
- C. Accuracy and AUC are different metrics and are generally not equal; AUC measures ranking ability across thresholds.
- D. Accuracy does not specifically overweight false positives — it weights all correct predictions equally, which is exactly why the huge majority class dominates.

Imagine a fire alarm that never goes off in a building that rarely has fires: it is "right" almost every day, but worthless when a fire actually starts.

📌 Exam tip: With imbalanced classes, ignore raw accuracy. Judge models on precision, recall, F1, and AUC. "Always predict the majority" can fake very high accuracy.

**Q7.** A random forest reduces overfitting compared with a single deep decision tree primarily by:
- A. Growing each individual tree deeper.
- B. Averaging many decorrelated trees grown on bootstrap samples with random feature subsets.
- C. Fitting each tree sequentially to the previous tree's residuals.
- D. Removing the need for a validation set.

**Answer: B**

The question asks how a random forest controls the high variance of a single deep tree.

A single deep tree overfits (high variance). A random forest builds many trees, each on a different bootstrap resample of the data AND using only a random subset of features at each split. The feature randomness decorrelates the trees, so when you average their predictions (or take a majority vote), the random errors cancel out and overall variance drops. The answer is B.

Why the others are wrong:
- A. Growing trees deeper makes individual trees overfit MORE, not less — the opposite of the goal.
- C. Fitting trees sequentially to the previous model's residuals describes BOOSTING, not a random forest. Random forests build trees independently (in parallel).
- D. Random forests do not eliminate the need for validation; you still validate to tune settings and estimate performance.

Think of asking many slightly different experts who each saw a different slice of the evidence, then averaging their opinions — the crowd's average is steadier than any single expert.

📌 Exam tip: Random forest = bagging + random feature subsets → decorrelated trees → averaging cuts variance. Boosting is the sequential, residual-fitting method (reduces bias too).

**Q8.** A support vector machine (SVM) classifier chooses its decision boundary by:
- A. Minimizing the within-cluster sum of squares.
- B. Maximizing the margin — the distance from the boundary to the nearest training points (support vectors).
- C. Averaging the predictions of many trees.
- D. Computing the probability of each class via a sigmoid.

**Answer: B**

The question asks for the central idea behind SVM classification.

An SVM looks for the separating boundary that is as far as possible from the closest data points of each class — it maximizes the margin. The few points sitting right at the edge of that margin are the support vectors, and they alone determine where the boundary sits. A wider margin tends to generalize better. The answer is B.

Why the others are wrong:
- A. Minimizing within-cluster sum of squares is the objective of K-means clustering, not SVM.
- C. Averaging predictions of many trees describes random forests / bagging, not SVM.
- D. Producing class probabilities via a sigmoid describes logistic regression; SVM output scores are not natural probabilities.

Think of drawing the widest possible "no man's land" road between two neighborhoods so each side has the most breathing room — the houses right on the edge define how wide the road can be.

📌 Exam tip: SVM = maximum-margin classifier; only the support vectors matter. The kernel trick adds nonlinear boundaries. SVM scores are not true probabilities.

**Q9.** In a neural network, the role of a nonlinear activation function (such as ReLU, $$\max(0, z)$$) is to:
- A. Reduce the number of weights that must be trained.
- B. Let the network model nonlinear relationships rather than just a linear combination of inputs.
- C. Guarantee the network cannot overfit.
- D. Replace the need for backpropagation.

**Answer: B**

The question asks why neural networks apply a nonlinear activation function at each neuron.

Each neuron computes a weighted sum of its inputs, $$w^\top x + b$$, which is linear. If you stacked only linear operations, the whole network would collapse into one big linear function — no matter how many layers. The nonlinear activation $$g(\cdot)$$ (like ReLU, sigmoid, or tanh) bends the output so that, with enough hidden units, the network can approximate almost any function, including highly nonlinear ones. The answer is B.

Why the others are wrong:
- A. Activation functions do not reduce the number of weights; the weight count comes from the network's architecture.
- C. Activations do NOT prevent overfitting — neural nets with many weights overfit easily; you fight that with validation, early stopping, regularization, and dropout.
- D. Backpropagation is still needed to compute gradients for training; the activation function does not replace it (in fact, its derivative is used during backpropagation).

Think of activations as the "bends" in a flexible wire: without bends, the wire is just a straight line; the bends let it trace any shape.

📌 Exam tip: Nonlinear activations are what give neural nets their power to model nonlinearity. Without them, stacked layers reduce to a single linear map.

**Q10.** An AUC (area under the ROC curve) of 0.5 indicates a classifier that:
- A. Is perfect.
- B. Is no better than random ranking.
- C. Has exactly 50% accuracy.
- D. Detects exactly half of the positive cases.

**Answer: B**

The question asks what an AUC of 0.5 means.

AUC is the probability that the model scores a randomly chosen positive case higher than a randomly chosen negative case. A perfect model has AUC = 1.0; a model that ranks no better than a coin flip has AUC = 0.5. So 0.5 means the classifier's ranking ability is no better than random. The answer is B.

Why the others are wrong:
- A. A perfect classifier has AUC = 1.0, not 0.5.
- C. AUC is about ranking quality across all thresholds, not accuracy at one threshold. AUC = 0.5 does not mean 50% accuracy (with imbalanced data accuracy could even be very high while AUC = 0.5).
- D. "Half of positives detected" describes a recall of 50% at a specific threshold — a different concept entirely from AUC.

Think of AUC as how well the model sorts good from bad: 0.5 is like shuffling a deck blindly — it puts positives above negatives only by chance.

📌 Exam tip: AUC = P(random positive ranked above random negative). 1.0 = perfect, 0.5 = random coin flip. It is a ranking measure, not an accuracy or recall figure.
